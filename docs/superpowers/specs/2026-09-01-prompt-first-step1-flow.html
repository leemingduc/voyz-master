2 · So why do the separate fields exist?

Short answer: the AI only ever receives one big text prompt, so for the AI itself the separate fields are not needed. They exist because plain Dart code, not the AI, consumes them in four places, and Dart needs machine-readable values, not free text.

FieldWho actually needs it (outside the AI prompt)After step 2?
departDate / returnDatenumDays is computed in Dart before calling the AI (plan and detail screens); saved-trip workspace shows the dates.Structure stays, filled by AI
destination, budget, interestsCache keys, so identical searches reuse a cached AI answer instead of paying for a new call.Structure stays, filled by AI

So the thing to remove is the manual typing, never the data structure. TripData keeps existing either way; the question is only who fills it in.

4 · What step 1 changes, precisely

  • Validation (smart_planner_screen.dart): only the prompt is required; destination, dates, budget, participants, age range all optional. New snackbar text: "Please describe your trip".
  • Labels only, no layout change: the "REQUIRED INFO" header becomes "TRIP DETAILS (OPTIONAL)" in en / vi / ko. Every component stays on screen.
  • Suggestions prompt: when the destination field is empty, stop hardcoding "Việt Nam"; instruct Gemini to infer destination, dates, and party size from the trip description.
  • Itinerary and detail prompts: include the trip description; when no dates were picked, let Gemini honor a day count stated in the prompt ("5-day trip"), defaulting to 3.
  • Cache fix: add aiPrompt (and dates/notes) to the suggestion and itinerary cache keys, so two different prompt-only searches no longer collide on the same cached answer.
